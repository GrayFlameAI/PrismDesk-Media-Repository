# PrismDesk 媒体宝库 — 批量操作联动、700+视频极限性能优化与自定义缓存目录方案

## 1. 核心问题诊断与解决原理（解决“250个截断”与“多出复制体” Bug）

### 1.1 为什么会出现“250个截断”与大目录卡死？
- **原因**：当目录下存在 700+ 个高清视频时，若一次性通过单次同步/大包返回或一次性在 DOM 中挂载全部节点，会导致 IPC 序列化阻塞及渲染层内存暴涨。
- **根治方案**：
  1. **IPC 分批流式传输（50 个/批）**：主进程 `fs:scanVaultStream`（及 Web Preview 后备流式分批接口）遍历物理目录时，每收集 **50 个文件元数据**即通过 `event.sender.send('fs:scanBatch', { scanId, batch, isLast, total })` 分批推送给渲染进程，彻底解除单次数量上限，700+ 乃至上万个视频均可完整加载。
  2. **虚拟网格（`react-virtuoso` 的 `VirtuosoGrid`）**：替换传统的全量 `.map()` 渲染，DOM 中始终仅挂载当前视口可见的 15~25 张卡片，700 个视频下内存稳定控制在 `< 150MB`，静止时 CPU `< 2%`。

### 1.2 为什么会出现“多出复制体”？
- **原因**：在分批累加状态（`setMedia(prev => [...prev, ...batch])`）与 `fs.watch` 磁盘热重载或手动刷新并发触发时，多次扫描批次交叉追加到同一个数组，或者同一物理路径因缺少唯一键去重而被重复压入状态列表。
- **根治方案**：
  1. **唯一扫描会话锁（`scanId`）**：每次发起扫描生成递增 `scanId`，渲染进程仅接收匹配当前最新 `scanId` 的分批数据包，自动丢弃过期扫描的残余批次。
  2. **基于物理路径 `Map<filePath, MediaItem>` 幂等合并**：在状态累加器中使用 `Map` 以规范化物理路径 `filePath` 作为唯一主键进行幂等去重合并，从根本上杜绝任何“复制体”产生。

## 2. 功能架构与实现模块

### 任务一：完整实现“批量操作”（多选 / 全选右键联动）
1. **右键菜单多选感知逻辑**：
   - 当用户在任意 `MediaCard` 上触发右键菜单（`onContextMenu`）时，检查该卡片的 `id` 是否在当前 `selectedMediaIds` 集合中：
     - **已在选中列表中（且选中数 ≥ 1）**：保持现有多选状态不变，将整个已选文件数组（`selectedMediaItems`）作为右键菜单的操作目标，菜单顶部显示“已选中 N 项媒体”。
     - **不在选中列表中**：自动将当前右键点击的卡片设为唯一选中项（或作为单文件目标）执行操作。
2. **批量移动（Batch Move）**：
   - 右键菜单点击“移动到...”选择目标分类或子文件夹后，向主进程发送 `fs:batchMoveMedia`，传入所有选中文件的物理路径数组 `filePaths` 与目标目录。
   - 主进程逐一安全移动文件（自动处理同名冲突），全部完成后前端统一刷新并清空选中状态。
3. **批量重命名（Batch Rename）**：
   - 多选状态下点击右键“重命名”，弹窗提示输入基础名称 `Base Name`（例如 `角色设定`），并实时预览命名规则。
   - 主进程 `fs:batchRenameMedia` 接收选中文件路径数组与 `Base Name`，根据文件总数自动补零附加序号（`< 100` 项使用两位补零如 `Name_01.mp4`, `Name_02.mp4`；`≥ 100` 项自动升级为三位补零 `Name_001.mp4`），严格保留各文件原始扩展名，并在重命名碰撞时安全回退。
4. **批量删除（移入系统回收站）**：
   - 右键菜单支持一键将全部选中文件释放句柄后移入系统原生回收站（`shell.trashItem`）。

### 任务二：极限性能优化（目标：700 个视频内存 < 150MB，CPU < 2%）
1. **安装并接入 `react-virtuoso`（`VirtuosoGrid`）**：
   - 在 `CategoryView` 与 `FolderView` 中使用 `VirtuosoGrid` 替代原有的全量网格 `.map()`，支持自适应响应式列数与紧凑间距，仅渲染可视区域内的卡片节点。
2. **IPC 分批流式扫描（50 个/批）+ 进度反馈 + 幂等去重**：
   - 主进程新增 `fs:scanChunked` / `fs:scanBatch` 通道，按 50 个文件一批流式返回给渲染进程；渲染进程通过 `scanId` + `Map<filePath, MediaItem>` 累加并实时展示加载进度，无截断、无重复。
3. **IntersectionObserver 视口懒加载 + 主进程 MD5 磁盘缩略图缓存（`.jpg`）**：
   - **缓存键计算**：以 `MD5(filePath + '_' + mtimeMs) + '.jpg'` 作为唯一文件名，保存在缩略图缓存目录中。
   - **工作流**：
     1. 当卡片滚动进入可视区（且静止 120ms 防抖）时，首先向主进程查询 `fs:getThumbnailCache`。
     2. 若磁盘已存在对应 `.jpg` 缓存文件，直接返回本地图片流 URL（无需创建 `<video>` 解码），瞬间显示且零内存开销。
     3. 若尚未缓存，则进入受控并发队列（最多同时 2 个任务）提取视频第 1 秒画面转为轻量 JPEG（质量 0.78，宽 360px），调用 `fs:saveThumbnailCache` 写入磁盘缓存目录，随后立即销毁隐藏 `<video>` 释放解码器缓冲区。

### 任务三：新增“自定义缩略图缓存目录”功能（保护 C 盘）
1. **默认路径与持久化配置**：
   - 默认路径：`path.join(app.getPath('userData'), 'thumbnails')`（沙盒环境下回退至 `.prism_thumbnails`）。
   - 持久化存储于 `prismdesk_app_config.json` 的 `thumbnailCacheDir` 字段。
2. **设置界面（`SettingsModal.tsx`）新增配置面板**：
   - 展示当前“缩略图缓存目录”完整物理路径及当前缓存占用统计（文件数与总大小）。
   - 提供 **“更改目录”** 按钮：调用 `ipcRenderer.invoke('fs:selectThumbnailCacheDir')` 唤起系统原生文件夹选择器（`dialog.showOpenDialog({ properties: ['openDirectory', 'createDirectory'] })`），支持自由选择 D 盘、E 盘等大容量磁盘目录。
   - **自动迁移并清理原目录**：当用户确认新目录后，主进程自动将原缓存目录中的所有 `.jpg` 缩略图流式迁移至新目录，清理原目录旧文件，并立即更新 `prismdesk_app_config.json`。
   - 同时提供 **“清理缩略图缓存”** 按钮，方便用户随时一键释放磁盘空间。
